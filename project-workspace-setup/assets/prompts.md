# 常用提示词

方括号里的内容要换成实际的。发送前检查有没有漏换的占位符。

## 搭建阶段

### 旧对话导出定稿（在原来的对话里发）

```text
我要新建一个项目来管理后续工作，需要你把这个对话里的内容整理成文件。规则：只写已经定下的结论，不写讨论过程；不确定或可能已经过时的内容，标注【待确认】。每份文件第一行写"最后更新：日期"。分开输出，Markdown格式。

【文件1：[名称]】[要包含的内容]
【文件2：[名称]】[要包含的内容]
【决策记录】按时间顺序列出所有已做出的决定，每条一行：日期｜来源｜内容｜理由｜影响谁。末尾单列"待决事项"：事项｜谁决定｜截止｜需要和谁对齐。
【当前状态】5–10行：现在处于哪个阶段、本周重点、已知风险、近期要定的事。
```

### 交叉核对文件（建项目前，可以在任意对话里做）

```text
我附上了准备放进新项目的全部文件。请逐项检查：
1. 编号撞车：同一个编号在不同文件里含义不同
2. 和《决策记录》冲突：包括文件里的"建议"和已定内容不一致
3. 过时的说法
4. 同一内容在几份文件里重复
5. 已经发生但文件没跟上的事
6. 缺少的基础信息（人名对照、称呼、联系方式）
7. 我名下的任务是否超出我的时间预算
8. 经常变的内容是否放错了地方（应该放进项目记忆或外部系统）
列一张问题清单：文件｜问题｜建议怎么改。能直接改的标"可直接改"，需要我决定的标"需要决定"。
```

### 初始化记忆（在协调器里发，附上两个 .md 文件）

```text
我附上了两个文件：决策记录.md、当前状态.md。请在项目记忆里新建两个记忆文件，并在MEMORY.md的索引里列出它们：
1.《决策记录》：按原文写入，保留表格结构，不要改写或合并。在索引里注明：内容冲突时以此为准。以后每次我确认【记录】，都按同样格式追加；待决事项定下来后移到"已做出的决定"。
2.《当前状态》：按原文写入，保留表格结构。以后每周由[进度类讨论串]更新，更新前先给我确认。
另外记住这些小约定：[例如编号写法"Issue #N""PR #N"、人名称呼]。
写完后告诉我：每个记忆文件记了多少条（决策记录应为已做出的决定[N]条、待决事项[N]条）；如果拆成了多个文件，索引里是否写清楚了顺序和新内容追加到哪一份。
```

### 开长期讨论串并试运行（在协调器里发）

```text
请开[N]个长期讨论串，各自先做一个小任务：
[讨论串A]：[一个当下真正需要的小任务，例如：为今天要做的决定列出方案、影响和建议，不要直接修改文件]
[讨论串B]：生成今天的每日简报。格式：今天要收什么（谁、交什么、按哪条标准看）；已逾期及卡住了谁；明天到期、今天要提醒的人；我今天要做的事（先列紧急的，不紧急的标"可延后"）；未确认的【记录】。只列清单。以后我说"今天的简报"就按这个格式，并把格式存进项目记忆。
[讨论串C]：[例如：审阅某个PR，只给我审阅报告和建议的评论内容，不要在外部发布]
```

### 设每日简报定时任务（在协调器里发）

```text
请设一个定时任务：每天早上[时间]由[进度类讨论串]生成当天的每日简报。
```

### 新文件上传后（在协调器里发）

```text
Library里新加了《[文件名]》，[它是什么]。以后[什么情况下]以它为准。
```

## 日常

### 晚上汇报（在进度类讨论串）

```text
今天收到的情况：（谁交了什么、谁没交、谁遇到了什么问题）。请更新进度，没交的按催交规则写好明天要发的私聊消息。
```

### 验收（在协调器）

```text
帮我验收（谁）的（什么，附任务编号）。
```

### 处理外部消息（在协调器，转发前删掉密钥）

```text
（贴原文）处理一下。
```

### 别人问细节（在协调器）

```text
（贴原文）这个按决策权限该谁定？给我一段可以直接回复的话。
```

### 一次性定时任务（在协调器）

```text
请设一个一次性定时任务：（日期、时间）由（哪个讨论串）做（什么）。
```

### 文件或指令更新后（在正在用它的讨论串）

```text
《（文件名）》更新了，请重新读一下。
```

## 阶段结束

### 阶段存档（在协调器）

```text
请开一个讨论串，生成"阶段存档_（阶段名）.md"：本阶段完成了什么、做了哪些决定（附理由）、遇到的问题和解决方式、还没解决的事、下一阶段重点；另写几条经验：哪些做法有效，哪些问题以后应该提前避免。同时检查项目记忆和Library里的文件是否需要更新，列出要改的内容给我确认。
```

### 让协调器复盘（用来改进本 skill）

```text
我在整理一份通用的《项目搭建与维护手册》，想把这个项目用下来的经验补进去。请回顾这个项目从建立到现在的情况（协调器里的对话、各讨论串汇报的结果、项目记忆、项目指令的改动、Library里文件的变化），整理：
一、踩过的坑：问题｜发生在哪｜原因｜当时怎么解决｜以后怎么避免（写成通用做法）
二、观察到的产品行为，尤其是和预期不一样的地方，每条注明"实际观察"还是"推测"
三、建立以后做过的调整，以及为什么改
四、目前觉得还不顺的地方，以及建议怎么改
要求：只写真实发生过的事，不确定的标【推测】；看不到完整过程的地方直接说明；每条尽量写成能用到其他项目的经验，项目细节放括号里当例子。直接在这里回答，不用开讨论串。
```

### 精简使用指南（用户熟悉以后）

```text
我要做一份精简的项目使用指南，只保留我还没实际操作过的部分。请根据协调器聊天、讨论串汇报和项目记忆，判断下面每一项我是否已经实际做过：[列出日常、每周、阶段结束的各项操作]。
另外列出：Library里每份文件最近一次更新、现在有没有已定但还没同步进去的内容；所有说好"以后再做""延后"的事项（内容、谁负责、什么时候开始）。
用表格输出，不确定的写【不确定】。直接在这里回答，尽量简短。
```
