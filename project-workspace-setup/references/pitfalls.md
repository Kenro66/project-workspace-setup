# 踩过的坑

来源：2026-10 小组 RAG 项目（见仓库 `practice-logs/`）。新实践里遇到的坑，按同样格式追加。

## 搭建阶段

| 坑 | 后果 | 做法 |
| --- | --- | --- |
| 提示词里的占位符原样发出去 | AI 什么都没写 | 发之前检查括号里的内容 |
| 从预览界面复制 Markdown | 表格结构丢失 | 用附件发送，或从纯文本编辑器复制 |
| 文件编号和资料里的编号撞车 | AI 混淆含义 | 文件用名称；加"编号说明"表 |
| 文件里的"建议"和已定决策并存 | 文件之间互相矛盾 | 交叉核对时以决策记录为准 |
| 给过时的文档直接标"定稿" | 旧内容被当成正式版本 | 先把内容更新到和当前决定一致，再标定稿 |
| 有错的发表资料、还在变的原文放进 Library | AI 拿错误或过时的内容当依据 | 只在《链接索引》里登记 |
| 一开始没定编号写法 | "#23"看不出是 Issue 还是 PR | 初始化记忆时就定好写法 |
| 团队成员不是仓库协作者 | 无法分配 Issue 和审阅人 | 建仓库当天邀请，同时开分支保护 |

## 运行阶段：协调器和讨论串

| 坑 | 后果 | 做法 |
| --- | --- | --- |
| 在协调器里回答某个讨论串的问题 | 细节对不上，或者传不到 | 在提问的那个讨论串里回答 |
| 在协调器里说"可以"来批准讨论串的操作 | 讨论串收不到 | 去讨论串里批准 |
| 改了项目指令，以为正在运行的讨论串也会遵守 | 旧讨论串还按旧规则做 | 去对应的讨论串里提醒 |
| 以为项目会主动提醒 | 错过截止日期 | 设定时任务 |
| 口头约定"到某个时间再查" | 讨论串不会到点醒来 | 设一次性定时任务 |
| 协调器凭记忆汇总进度 | 漏掉讨论串的最新结果 | 指令里要求先读讨论串最新汇报 |
| 讨论串显示"等你处理"，其实已经做完 | 误以为还有事 | 看最后一条汇报；每周把做完的标为已完成 |
| 协调器被替换 | 口头约定丢失 | 所有约定写进记忆 |
| "先提方案、确认后再开讨论串"用于所有任务 | 用户几乎每次都只回"开"，多一轮来回 | 长期讨论串直接做；只有新开临时讨论串才问 |

## 运行阶段：记忆和文件

| 坑 | 后果 | 做法 |
| --- | --- | --- |
| 记忆文件写长了 | 被拒或被拆散，顺序乱 | 每份约 4KB，按部分规划，索引写清楚 |
| 【记录】要确认才写入 | 积压，忘了确认 | 简报末尾列出未确认的【记录】 |
| 在文件右键菜单里找 Replace | 找不到 | Replace 是上传同名文件时的提示 |
| 下载后文件名被改成"xxx (1)" | 上传后变成两份 | 上传前改回原名 |
| Replace 漏了一次 | 同一份文件两个版本 | 每周检查一次 |

## 运行阶段：对外消息和协作

| 坑 | 后果 | 做法 |
| --- | --- | --- |
| 规则只写进文件，没告诉团队 | 只有 AI 知道 | 定下来后用简短版本发给相关的人 |
| 讨论串还没核对源文件，协调器就起草了对外消息 | 消息和讨论串的结论冲突 | 技术类消息等负责的讨论串核对完再起草 |
| 草稿沿用了已被推翻的分工 | 发出错误的分工 | 起草前对照《决策记录》里最新的同类决定 |
| 给别人的消息写"对照《某文件》第几节" | 对方看不到项目文件 | 直接写要点哪里、应该看到什么 |
| 群消息一次塞进所有细节 | 没人看 | 每人 2–3 行，细节放任务系统 |
| 草稿里写了具体时间点 | 发出时已经过期 | 草稿只写日期，时间点由用户发送前填 |
| 转发的外部消息带着密钥 | 泄露风险 | 转发前删掉；AI 不写进任何文件 |
| 用户名下的任务太多 | 关键路径被卡住 | 先做会卡住别人的事，其他的延后并记录 |
| 有上下游依赖的任务（例如互相依赖的 PR） | 一个卡住，后面全部顺延 | 截止提前一天，一早排好顺序，任务里写清上下游 |
| PR 写"Related to #N" | Issue 没有自动关闭 | 写 `Closes #N`，用 PR 模板 |
| PR 作者不能批准自己的 PR | PM 自己的 PR 合不进去 | 分支保护给管理员留绕过权限 |
