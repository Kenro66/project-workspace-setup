# 日常与定期维护

## 1. 在哪做什么

| 在哪 | 做什么 |
| --- | --- |
| 协调器 | 开新任务；简单问答、概念答疑、单条消息的翻译或改写；跨几个讨论串的事；问整体进度；问"下一步做什么""这件事去哪做" |
| 长期讨论串（按领域，2–4 个） | 属于它的工作直接交给它做，不用先问 |
| 临时讨论串 | 验收、需要多轮修改的正式消息、单次产出；新开前先告诉用户名称和用途 |

- 某个讨论串提出问题、等用户决定时，用户**在那个讨论串里**回答，细节都在那里
- 批准操作要在讨论串里点
- 用户最常问的就是"该在哪回"，所以这条要写进《工作方式》

## 2. 每天

| 时间 | 在哪 | 做什么 |
| --- | --- | --- |
| 早上 | 进度类讨论串（定时任务自动生成） | 每日简报：今天要收什么、谁逾期、谁被谁卡住、明天到期要提醒谁、用户今天先做什么、还没确认的【记录】。需要通知别人的，简报第一条直接写成可以转发的消息 |
| 白天 | 各讨论串 | 先做会卡住别人的事，再做自己的文档工作；回答讨论串等待中的问题 |
| 有截止时刻的事 | 外部系统 | 到点前看一眼；需要提醒的设一次性定时任务 |
| 晚上 | 进度类讨论串 | 用户报告今天收到了什么、谁没交；讨论串更新进度，准备好明天的提醒 |

## 3. 每周（建议周五）

1. 把周报贴进进度类讨论串，让它更新《当前状态》，用户确认后写入
2. 从外部事实来源生成甘特图等报表
3. 用户去 设置 → 记忆 扫一眼《决策记录》和《当前状态》
4. 本周改过的文件，按第 5 节 Replace；检查有没有同一份文件的两个版本
5. 把做完的讨论串标为已完成（状态不会自己更新）

## 4. 阶段结束

1. 让协调器开一个讨论串，生成阶段存档放进 Library（提示词见 `assets/prompts.md`）：完成了什么、做了哪些决定、遇到的问题、还没解决的事、下一阶段重点、几条经验
2. 同时让它列出项目记忆和 Library 文件哪些要更新，用户确认后更新
3. 清理讨论串：做完的标为已完成，上一阶段的临时讨论串不再用
4. 能通用的经验，带回去更新本 skill

阶段存档是给用户看的：以后想了解整体情况就看存档，不用翻聊天记录。

## 5. 改文件的流程

1. 告诉负责的讨论串要改什么，它把新版本写在共享文件夹里
2. 用户下载新版本，检查文件名和 Library 里的原文件完全一致（浏览器常改成"xxx (1).md"）
3. Library「添加」→ 选这个文件 → 提示同名时选 Replace；没有提示就先删旧文件再上传
4. 点开文件看第一行"最后更新"，确认换好了
5. 有讨论串正在用这份文件的，去那个讨论串里说"《某文件》更新了，请重新读一下"
6. 新加的文件（不是替换），在协调器里说一次它是什么、什么时候以它为准

改项目指令也一样：只对新讨论串生效，正在运行的要去提醒。

## 6. 用户想要一份使用指南时

用户熟悉以后，指南只保留他还没实际操作过的部分。先让协调器对照聊天记录判断哪些已经做过（提示词见 `assets/prompts.md` 的"精简指南"），再据此写。不要给熟练用户一份面面俱到的长指南。
