# 场景：求职申请

状态：**未实践**。以下是根据核心原则推出来的初始建议，使用时要和用户一起确认，实践后按结果修改，并去掉本行。

## 适用情况

用户同时申请多个岗位，需要管理材料、截止日期和沟通。

## 文件结构（建议）

**Library**

| 文件 | 内容 |
| --- | --- |
| 《求职总览》 | 目标岗位、地区、时间线、个人优势、不考虑的方向及理由 |
| 《简历素材库》 | 经历、成果、数据。只写确认过的事实，不写夸大的说法 |
| 《沟通规范》 | 邮件模板、称呼、语言、署名 |
| 《链接索引》 | 简历各版本、作品集、招聘页面的位置 |
| 《工作方式》 | 每天、每周怎么用这个项目 |

**项目记忆**：《当前状态》（本周目标、在进行的申请）、《决策记录》（例如"不投某类公司"及理由）

**外部事实来源**：申请进度表（表格或看板），每条一行：公司｜岗位｜状态｜截止｜下一步

## 讨论串（建议）

| 讨论串 | 负责 |
| --- | --- |
| [申请材料] | 按岗位改简历和求职信，只用《简历素材库》里的事实 |
| [进度] | 每日简报：今天截止的、要跟进的、等回复的 |
| [面试准备]（临时） | 针对某一场面试，每次新开 |

## 注意

- 不经确认不发送任何邮件和申请
- 简历和求职信只能用素材库里确认过的事实
- 招聘页面可能会下线，需要的信息要保存原文，不只存链接

## 待实践验证的问题

- 申请进度表放在哪个系统，讨论串读写最方便
- 简历的多个版本怎么管理才不会混乱
