# 场景：日程与生活管理

状态：**未实践**。以下是根据核心原则推出来的初始建议，使用时要和用户一起确认，实践后按结果修改，并去掉本行。

## 适用情况

用户想用一个项目管理自己的日程、习惯、学习计划等个人事务。

## 文件结构（建议）

**Library**

| 文件 | 内容 |
| --- | --- |
| 《生活总览》 | 长期目标、固定安排（课程、工作时间）、优先级原则（例如"睡眠优先于熬夜赶工"） |
| 《工作方式》 | 每天、每周怎么用这个项目 |

**项目记忆**：《当前状态》（本周重点）、《决策记录》（作息、预算等自定规则及理由）

**外部事实来源**：日历（通过日历连接器读取，不复制进项目）、待办清单

## 讨论串（建议）

| 讨论串 | 负责 |
| --- | --- |
| [每周计划] | 每周日排下周：重点、时间块、要推掉的事 |
| [每日简报] | 定时任务每天早上生成：今天的安排、要准备的东西、提醒 |

## 注意

- 个人敏感信息（健康、财务、证件）只放必要的部分
- 创建或修改日历事件、发消息等对外操作，必须先确认
- 个人项目没有团队规则，《项目总览》可以很短

## 待实践验证的问题

- 日历连接器在讨论串里能读到多少信息，能否直接写入
- 每日简报对个人项目是否有用，还是每周计划就够了
- 记忆里的"作息规则"能否有效影响建议
