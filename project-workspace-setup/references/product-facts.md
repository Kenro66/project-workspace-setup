# 产品事实

最后核对：2026-10-29

标记说明：【官方】来自官方文档 https://code.claude.com/docs/en/claude-projects.md ；【观察】是实际使用中看到的，没有官方说明，可能随版本变化。用之前先对照官方文档，不一致时以官方文档和用户界面为准。

## 1. 两种项目

| | 旧版项目（claude.ai 聊天 / Cowork） | 新版项目（协调器 + 讨论串） |
| --- | --- | --- |
| 结构 | 一组对话 + 参考文件，像"分组" | 一个协调器对话 + 它开出的讨论串 |
| 旧对话 | 可以移进来 | 文档没有说可以移入，当作不能 |
| 信息传递 | 用户在对话之间复制粘贴 | 协调器分派和汇总 |
| 可用计划 | 各计划 | 公开测试中，Pro、Max；Team、Enterprise 暂不可用【官方，2026-10】 |

## 2. 结构

- **协调器**：项目里唯一的长期对话。接收用户消息，决定自己回答还是开讨论串，跟踪所有讨论串。只看最近的消息、最近的讨论串和项目记忆，不读完整历史；看得到讨论串汇报的结果，看不到每一步过程【官方】
- **讨论串**：干活的单位，各有自己的上下文。通常在云端运行，关掉电脑也会继续；做完向协调器汇报；会自动压缩上下文；一周没有动静会被自动标为完成【官方】
- 讨论串之间不直接沟通，共享信息靠项目记忆、共享文件夹和协调器转达【官方/观察】
- **概览面板**：按状态列出讨论串（等你处理、进行中、待审阅、已结束、已完成），还有 Library 和 Pull requests 标签页。Pull requests 页只显示讨论串自己开的 PR【官方】
- 讨论串的状态可能过时：事情做完后仍显示"等你处理"或 blocked。以讨论串最后一条汇报为准，做完的由用户手动标为已完成【观察】
- 协调器可能被替换，新的只拿到之前对话的一份摘要，没写进记忆的口头约定会丢【观察】
- 协调器回答"进度如何"时，可能只凭记忆汇总、漏掉讨论串的最新结果；要在项目指令里要求它先读讨论串的最新汇报【观察】
- 一次性的大任务可以单独开讨论串，避免占用协调器的上下文【观察】

## 3. 云端讨论串开始时带着什么【官方】

- 项目指令
- 项目记忆（先读 MEMORY.md 索引，需要时再打开其他记忆文件）
- Library 里的文件（`/mnt/project-files`）
- 项目仓库，以及仓库根目录的 `CLAUDE.md`（不包括仓库里的 skills、`.mcp.json`、`.claude/settings.json`）
- 用户 claude.ai 账号里的连接器
- 云环境

在用户自己电脑上运行的讨论串，读项目指令，但不加载项目记忆。

## 4. 项目指令

- 位置：项目设置 → 记忆 → 项目指令，上限 16,000 字符【官方】
- 发给每个新讨论串和协调器。改了以后，已经在运行的讨论串不受影响，要去那个讨论串里提醒它【官方】
- 应包含：项目做什么、在哪里工作、讨论串怎样自查、缺东西时怎么办、哪些操作必须先问用户【官方】

## 5. 项目记忆

- Claude 写的笔记，存成文件：MEMORY.md 是索引，其他是记忆文件。用户说"记住……""忘掉……"来增删，也可以在 设置 → 记忆 里查看、修改、删除【官方】
- 是笔记，不是强制规则；必须严格执行的写进项目指令【官方】
- 每个记忆文件上限约 4KB，长内容会被拆成多份。要按"第 N 部分"规划，索引写清楚各部分范围、阅读顺序、新内容追加到哪一份【观察】
- 协调器和讨论串共用同一份记忆，写之前要先读最新版，否则写入会被拒【观察】
- 适合放短的、经常变的内容；长的、基本不变的放 Library【观察】

## 6. Library

- 位置：项目主页面的概览面板 → Library 标签页 → 添加。不在设置窗口里【观察】
- 上传的是副本，电脑上的文件改了不会同步，要重新上传【官方】
- **Replace 不在文件的右键菜单里**：点"添加"，选同名文件，弹出"已有同名文件"的提示时选 Replace【官方】。浏览器下载时常把文件名改成"xxx (1).md"，名字不一致就不会出现提示，会变成两份；上传前先改回原名。没有出现提示时，先删除旧文件再上传也可以【观察】
- 限制：新建对话框里超过 30MB 的文件会被跳过；每次最多 100 个文件、2GB，单个文件最大 480MB；文件夹只取前 100 个文件、200MB，项目最多 10 个文件夹【官方】
- Claude 改不了用户上传的 Library 文件。讨论串改好的版本写在共享文件夹里（Library 面板里显示为子文件夹），用户要下载后 Replace【观察】
- 在对话里发的附件不会变成 Library 文件，而是存在共享文件夹的 uploads 目录里【观察】
- 同一份文件可能同时出现在用户上传区、共享文件夹和讨论串附件里，Replace 漏一次就会有两个版本【观察】
- 讨论串读不到 claude.ai 上的 artifact 链接、Google Docs 链接、Slack、微信等内容；需要的资料要导出放进 Library、粘贴原文，或者通过连接器读取【观察】

## 7. 设置项

| 设置 | 说明 | 建议 |
| --- | --- | --- |
| 协调器模型 / 思考强度 | 协调器用 | Opus / 中等（主要做分派） |
| 讨论串模型 / 思考强度 | 新讨论串的默认值 | Opus / 高；额度紧张时，简单任务在任务里说"用 Sonnet 做" |
| 使用限额重置后自动继续 | 额度用完的讨论串在重置后接着做 | 开 |
| 环境 → 项目仓库 | 每个云端讨论串都会克隆 | 只加几乎每个任务都要用的仓库 |
| 环境 → 允许使用设备 | 讨论串能否在用户电脑上运行 | 开着也行，只在需要时用到 |

官方文档写的默认值是"讨论串高、协调器低"，界面上可能不同，以界面为准。

## 8. GitHub

- 前提：Claude 的 GitHub App 装在仓库上（github.com/settings/installations → Repository access），用户对仓库有推送权限【官方】
- 讨论串在自己的分支上工作，需要时开 PR【官方】
- commit 作者是用户本人的账号，带 Claude 的 co-author 标注；评论只能以用户账号发，不能代表别人。标注别人的贡献用 `Co-authored-by`【观察】
- 只有仓库协作者才能被设为 Issue 负责人或 PR 审阅人【观察】
- PR 作者不能批准自己的 PR（GitHub 的限制）。开分支保护时要给管理员留绕过权限【观察】
- PR 正文写"Related to #N"不会自动关闭 Issue，要写 `Closes #N`【观察】
- Issue 和 PR 共用一套编号，消息里要写"Issue #N""PR #N"【观察】

## 9. 其他

- 讨论串需要批准某个操作时，要在那个讨论串里批准，在协调器里说"可以"传不到它【官方】
- 用户可以在讨论串自己的输入框里直接说话，消息不经过协调器【官方】
- 协调器可以设定时任务。没有设的话，项目不会主动提醒用户【官方】
- 每天的简报定时任务按时在指定的讨论串里生成，只发在讨论串里，不会通知用户或发到别处【观察】
- "到某个时间再做"不会自动执行，讨论串不会到点醒来；要设一次性定时任务【观察】
- Slack 连接器只开放给 Team、Enterprise，并要求工作区管理员先安装 Claude 应用；学校或公司的 Slack 多半连不上。替代做法：在 Slack 里把重要的人设为 VIP，收到消息后复制原文给协调器【官方，2026-10】
- 用户转发外部消息时可能带上密钥；AI 不能把密钥写进记忆或任何文件，并提醒用户删掉【观察】
